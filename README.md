# GSB Bugfix Task
## 题面
企业出口的 DNS 安全分析上线后，误报把几个正常业务域名拉黑了，真正的隧道却从眼皮底下过去。dns_tunnel_scorer.py 的 TunnelScorer 负责打分和窗口统计，现在只看单标签熵，合法 CDN 的随机子域被大量误报；查询长度按字节算不按标签数算，超长域名反而漏判；TXT 响应大小没参与打分，短查询长应答的隧道直接放过；统计窗口固定整点切分，跨窗口的慢速隧道永远到不了阈值；NXDOMAIN 比例没算，攻击者用大量失败查询做信标也不报警；白名单按后缀匹配，恶意子域挂在可信域名下就放行；同一客户端的多路并发查询没有聚合，每一路都低于阈值；分值只增不减，一次误报之后域名永久拉黑；采样只取前一百个包，突发隧道的后半段完全缺失；响应时间抖动没建模，正常递归超时被当成心跳；IDN 同形字没归一，黑白名单都能绕；多实例各自维护计数，横向扩容后阈值直接翻倍。安全运营说误报名单里有一半是业务方刚上线的 CDN 域名，而真正有问题的那个域名，得分一直停在中低区间，他们要求先能把两类分开，再调阈值，现在很头疼。要求打分能同时压住误报和漏报，窗口、采样和多实例状态要一致。仓库里的十五个用例，现在全军覆没。

## 运行方式

```bash
python -m pytest tests -q
```
