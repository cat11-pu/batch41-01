# GSB Bugfix Task
## 题面
企业 SIP 注册服务器这周出现分机互相串线，还有外部分机冒充内部号码打进来。sip_register_guard.py 的 RegisterGuard 负责注册和事务匹配，现在 REGISTER 的 Call-ID 和 CSeq 不校验，同一个注册请求能被重放；nonce 固定不变，摘要认证抓一次包就能复用；Contact 里带多个地址时只保存第一个，呼叫总落到已经关机的旧终端；expires 为 0 不删除绑定，注销以后还能打进来；同一个 AOR 多终端注册时向所有 Contact 分叉，接听的人对不上；Via 的 branch 不校验，响应被送到错误的事务；源地址和 Contact 域名不一致也接受，注册可以被中间人劫持；Authorization 里的 URI 和 Request-URI 不一致也放行；注册刷新没有最小间隔，终端频繁刷新把数据库打满；传输从 UDP 切到 TCP 后事务状态没迁移，响应直接丢；401 挑战的 qop 不支持也接受，认证被降级到无 qop；批量注册没有限速，攻击者能枚举整个号段。运维已经把外线入口临时关掉，只留内部互通。这套注册服务器还连着呼叫中心和门禁对讲，停一次影响面很大，厂商说升级要停机四个小时，运维一直没敢排窗口，现在只能靠临时黑名单顶着，客服那边已经炸了，现在大家都在等答复。要求注册绑定、挑战和事务三层状态一致，任何伪造注册都不能覆盖合法绑定。十五个用例从头验到尾，没有一条能成立。
