# GSB Bugfix Task
## 题面
直播连麦四分屏上线后，快的那一路越来越超前，嘉宾声音和口型差三百毫秒；每路 PTS 用各自时基，音频只跟主路，其他嘉宾的声音按到达顺序混；某路掉帧后时间线被压缩，后续画面整体加速；布局切换时新渲染目标没预分配，切过去黑一帧；画中画缩放用最近邻，聊天文字锯齿明显；多路同时到达时按完成顺序合成，画面层级每帧都在变；可变帧率源按固定帧率取帧，出现重复帧和丢帧；某路断流后画面冻结，没有占位提示，观众以为卡死；十比特 HDR 源和八比特 SDR 源混用，颜色整体发灰；合成线程和编码线程共用帧队列，读写出队竞争，偶发重复帧；布局参数为零宽或区域越界时没有拒绝；四路 1080p 合成每帧 8ms，超出预算。multiview_compositor.py 的 MultiviewCompositor 要把各路时间戳统一到主时钟并按最近帧选取，音频按统一时间轴对齐，掉帧时做时间补偿而不是压缩后续，布局切换前预分配目标，缩放用双线性或更好的采样，合成顺序按布局固定，可变帧率按真实时长取帧，断流显示占位并保持时间线，色彩转换按输入元数据做，帧队列原子交换，非法布局拒绝，超预算降低合成分辨率并记录，输出布局、端到端延迟和丢帧统计。现有十五条用例全部处于失败状态。

## 运行方式
```bash
python -m pytest tests -q
```
