## 题面
十九点四十到二十点十分这半小时的排障记录，基本把自定义房间的座位问题串了一遍。十九点四十三，有个人用两台设备各点一次加入，名单里冒出两个同名实体，开局其中一个立刻掉线；十九点四十七，观战位的人按了准备，整支队伍的准备标记被清空；十九点五十二，房主网络断开，系统把权限交给了观战席，剩下五个人点开始毫无反应；十九点五十五，有人换边，客户端显示已经过去，服务端人数仍是四打六，倒计时照常走；十九点五十八，房间已经解散，大厅列表里还留着入口，点进去报未知房间；二十点整，掉线的人重连，按座位号找回却撞上补位的新人，两个连接同时收包；二十点零二，邀请链接被同一账号点了两次，第二个人被顶出房间；二十点零五，倒计时最后一秒有人退出，计时器没有取消，开局少一人；二十点零七，两个大区的房间号各自从零开始，撞号后一队人进了另一场；二十点零八，房主迁移途中有人申请加入，座位锁卡住不再释放；二十点十分，客户端缓存的准备状态在切图后还显示已准备，服务端那边根本没收到。room_seat_ledger.py 的 SeatLedger 里，加入、准备、退出、移交和重连五个入口分别被不同的人改过。座位占用要有唯一约束，加入离开可重入，房主按加入顺序移交并跳过观战，准备与否只认服务端那份状态，房间生命周期与列表同步，倒计时里人数变化重新校验，房间号带区标识，重连认人不认座，锁带超时。test_room_seat_ledger.py 那套检查一共十五项，我跑了三遍，没有一项通过。
