# GSB Bugfix Task
## 题面
自研内核模块改成强制验签以后，测试机还能加载一个没签名的调试版本，安全评审要求查清楚。摘要算法用 SHA-1 的模块仍然被接受；签名密钥不在信任钥匙环里也能加载；签名段被整个剥掉，加载流程没有拦住；模块版本魔数和当前内核不匹配，照样插进去，加载后直接崩；同名不同版本的模块共存，先加载的那个一直生效；密钥吊销以后缓存还放行了好几个小时；模块参数不在白名单里也能随便传；强制模式下内核自带的模块被误判成未签名；依赖模块没签名，跟着主模块一起被加载；证书链中间缺一环的，也被当成完整链路放行；同一模块卸载后再装回来，上一次的签名结论还留着；加载失败时错误码被吞掉，日志里只剩一行看不出原因。kmod_signature_gate.py 的 ModuleSignatureGate 要解析 ELF 段和 PKCS#7 签名，摘要算法只允许白名单，校验证书链与钥匙环，检查吊销状态，比对版本魔数，依赖模块逐个验签，模块参数按白名单过滤，强制模式下内置模块走豁免表，所有失败返回明确错误码和原因。我换了三种加载顺序去跑那十五项，结果都一样，全不对。

