# GSB Bugfix Task
## 题面
客服系统上线代客登录以后，工单关闭了会话还挂着，安全团队抽查发现好几起超时访问。工单已经关闭两小时，代登录会话仍然存活；代登录令牌能调用写接口，而产品定义里只允许只读；同一个客服同时代登录五个用户，超过策略上限也没人拦；双人审批流程最后只记了一个审批人；被代登录的用户完全收不到通知；管理员点撤销只删了本地会话，令牌在别的服务还能用；代登录令牌和普通用户令牌用同一个受众，后端根本区分不出来；审批通过后工单被转派，授权还绑在原来的工单上；时限参数填了负数，反而变成永久有效；审计日志只写客服 ID，没有目标用户，出了事对不上。support_impersonation_grant.py 的 ImpersonationGrantBook 要把授权绑定到工单和具体目标用户，权限限定只读范围，时限设上下限并拒绝非正数，双人审批必须两个不同主体，撤销要传播到所有下游，令牌使用独立受众，工单转派或关闭即失效，通知和审计双向记录。test_support_impersonation_grant.py 的十五个用例现在全部报错，覆盖工单关闭、写接口、并发上限、单审批人、用户通知、撤销传播、受众混用、转派失效、负数时限、审计缺目标、过期授权、重复审批、空工单、跨租户和账本隔离。

## 运行方式
```bash
python -m pytest tests -q
```
