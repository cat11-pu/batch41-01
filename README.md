# GSB Bugfix Task
## 题面
公司同时接了企业微信、飞书和 Azure AD 三个身份源，同一个员工往往有三四个账号，运营提了自动合并，结果第一次灰度就出了越权。两个账号邮箱相同但 issuer 不同，被直接合并，其中一方能登进另一方的空间；没验证过的邮箱也被当成合并依据；合并事务跑到一半用户正好登录，一边写一边读，会话最后挂在错误的账号上；合并完成后旧账号的 refresh token 还能继续换令牌；管理员发现合错了想解绑，原账号的资料已经被清空，回滚不了；整个合并过程没有留下能追溯的操作记录；同一个邮箱大小写不同被判成两个人，反而生成了重复账号；某个 issuer 的 sub 因为重新注册变了，系统把他当成新用户；管理员强制合并没有二次确认；合并时组成员关系被静默丢掉。identity_link_merge.py 的 IdentityLinkMerger 要以 issuer 加 sub 作为主键，邮箱只能作为提示不能作为唯一依据，合并走事务并写可回放的补偿日志，完成后立刻失效旧会话和刷新令牌，重复请求保持幂等，出现冲突时返回候选账号而不是自动选一个，组关系要么迁移要么明确报告。test_identity_link_merge.py 的十五个用例现在全部报错，分别压同邮箱跨 issuer、未验证邮箱、并发登录、旧令牌、解绑回滚、审计缺失、大小写、sub 变更、强制合并、组丢失、重复合并、空 issuer、跨租户、事务失败和快照隔离。

## 运行方式
```bash
python -m pytest tests -q
```
