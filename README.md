# GSB Bugfix Task
## 题面
协议组把自研二进制协议的模糊测试接进流水线，跑了一周，报出来的崩溃有一半复现不了。frame_fuzz_oracle.py 的 CrashOracle 负责判定、去重和最小化，现在合法的边界输入被判定成崩溃，语料库越跑越小；超时和崩溃用同一个结果码，去重时把挂起当成崩溃；同一输入跑两次结果不同，oracle 被上一轮的全局状态污染；只按栈顶地址去重，不同根因被合并成一个；最小化之后无法复现，缩减器把真正的触发条件删掉了；种子语料在迭代中被原地修改，回放结果每次都不一样；sanitizer 报告只解析第一种错误，后面的真实问题被掩盖；子进程崩溃后没回收，僵尸进程占满进程表；模糊器重启后覆盖率位图没落盘，每轮都从零开始；变异用的随机种子没记录，崩溃样本无法复现；目标协议是有状态的，每个用例都从握手开始，吞吐只有几十次每秒；内存上限只限制单次分配，累计泄漏把整台机器拖垮。协议组现在不敢把模糊测试结果直接当漏洞，怕又白跑一轮，他们希望先能稳定复现，再谈覆盖率，流水线每天还在跑，误报把值班群刷得没人看。要求判定、去重、最小化和复现形成闭环，误报和漏报都要能解释。十五条用例一条条跑下来，没有一条通过。

## 运行方式
```bash
python -m pytest tests -q
```
