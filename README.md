# GSB Bugfix Task
## 题面
审计写入在高峰期开始限流以后，运维还在群里说链路一切正常，合规抽查发现中间少了一段，系统那边一点动静都没有。队列满的时候直接丢弃，缺口没有记下来，连丢弃的条数也没有留下来；丢弃区间没有合并，缺口列表几分钟涨到几十万条；高优先级的安全事件和普通访问记录挤在同一条队列，被一起丢掉；数据还没落盘就先回了确认，进程崩溃后整段消失；重试让同一条内容重复投递，消费端没有去重；同一个会话的登录和登出顺序颠倒，时间线对不上；磁盘写满时生产者无限阻塞，把业务线程也拖死；一个租户刷日志就能占满全平台配额；缺口标记本身也挤在同一条队列里，丢了以后谁也不知道；为了降量还对记录做了采样，合规要求全量保留。audit_gap_ledger.py 的 AuditGapLedger 要有界队列并按优先级分道，缺口按区间合并后持久化，落盘成功才确认，消费端按键幂等去重，同一主体的记录保序，磁盘压力时非阻塞转储，按租户配额限流，缺口标记单独走可靠通道，记录禁止采样。压测一开，那十五项检查就整片红了。
