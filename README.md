# GSB Bugfix Task
## 题面
帧同步对局在弱网和低端机上节奏完全乱套，选手说同样的连招在训练场能打出来，进比赛就慢半拍。服务器逻辑帧按墙钟推进，客户端按渲染帧追，掉一次帧就一次补好几帧；追帧没有预算上限，补帧风暴把 CPU 打满，下一帧更慢；暂停菜单打开时服务端还在跑帧，恢复后客户端从暂停那一帧继续；断线重连只收到最新帧，缺席那几帧的输入直接没人补；观战者加入会改变帧广播节奏，选手收到的帧间隔开始抖；多个帧包被合并发送，客户端按到达时间拆包，顺序错乱；低端机请求降帧，服务端直接改全局帧率，所有人的技能冷却一起变慢；帧间隔校验用客户端时间，改系统时间就能加速；回放文件按渲染帧写，和逻辑帧对不上；房间里一个人卡顿，服务器等所有人确认，整房停住；帧号回绕后比较大小用了有符号数，追帧判断反了。lockstep_clock.py 的 LockstepClock 负责 advance、catch_up、pause、resume 和 broadcast，现在每条路径各算一套时间。希望逻辑帧固定步长，追帧有预算且不跳过逻辑帧，暂停和恢复原子切换，重连补齐缺席帧，观战走独立广播，帧包带序号，单人降帧只影响表现，时间以服务端为准，回放按逻辑帧记录，慢客户端丢帧不阻塞全房，帧号回绕按无符号处理。test_lockstep_clock.py 的十五条用例眼下全部失败，压补帧风暴、暂停恢复、重连补帧、观战抖动、拆包乱序、全局降帧、客户端时间、回放对齐、慢客户端、帧号回绕和广播隔离。

## 运行方式
```bash
python -m pytest tests -q
```
