# GSB Bugfix Task
## 题面
边缘清洗设备上线 SYN cookie 后，攻击是挡住了，正常用户也开始大面积连不上。syn_cookie_guard.py 的 SynCookieGuard 负责半开队列和 cookie 校验，现在 SYN 队列满后不启用 cookie，直接把所有新连接丢掉；cookie 只用源地址计算，换个源端口就能绕过限速；MSS、窗口缩放和时间戳选项没编码进 cookie，重放后参数全丢；ACK 的序号不校验，伪造一个 ACK 就能建连接；cookie 密钥轮换没有重叠期，轮换瞬间正常握手全部失败；半开连接超时写死，长 RTT 用户总被误删；SYN-ACK 重传没有退避，攻击流量下又叠一层重传风暴；只统计 SYN 不统计 ACK，正常业务高峰被误判成攻击；代理后面的真实源地址没解析，所有用户共用一个 cookie；IPv4 和 IPv6 共用一张哈希表，冲突把正常连接挤掉；白名单只按单个地址配，CDN 大段地址被误杀；攻击停止后 cookie 模式不退出，性能一直上不去。值班同学现在只能手动放宽阈值，攻击一回来又得收紧。清洗设备刚上线，阈值还在摸索，运维不敢把防护关掉，业务侧只看到连接超时，根本不知道是清洗层的问题，两边现在每天都要对一次流量，厂商支持响应很慢，现场运维压力很大，大家都盯着这件事，只能先顶着。要求队列、cookie 和统计三部分协同，攻击流量和正常流量要能分开处理。这十五个用例目前一条都没跑过。

