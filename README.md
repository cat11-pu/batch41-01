# GSB Bugfix Task
## 题面
登录服务扩到八个实例以后，撞库攻击反而更容易了，同一个账号被打了几百次都没触发锁定。八个实例各自在本地内存计数，每个实例失败四次，全局永远到不了阈值；实例重启后计数直接清零；用户成功登录只清了当前实例的计数，另外七个还留着；锁定窗口按各节点自己的时钟算，节点之间差三分钟，有的提前解锁；攻击者换了一千个 IP 打同一个账号，IP 维度限流触发了，账号维度却没人管；管理员手工解锁后，旧计数马上又被异步任务回填；锁定期间接口返回“密码错误”，用户以为记错密码，反复重试把窗口越拖越长；并发失败请求读改写打架，计数丢了一截；锁定键里混进了密码哈希，用户改完密码锁定自动失效；审计里同一次锁定写了二十条重复记录。lockout_quorum.py 的 LockoutQuorum 要用集中存储做原子递增，维护滑动窗口和成功清零，账号与来源 IP 两个维度分别判定，管理解锁带版本号防止回填，错误码统一为已锁定，审计按事件去重，时间一律以服务端为准，锁定键只包含规范化后的账号标识。test_lockout_quorum.py 的十五个用例目前全部失败，分别压多实例计数、重启清零、成功清零、时钟偏差、双维度、解锁回填、错误码、并发丢失、键污染、审计重复、窗口滑动、空账号、超长账号、跨租户和状态隔离。

## 运行方式
```bash
python -m pytest tests -q
```
