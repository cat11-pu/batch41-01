# GSB Bugfix Task
## 题面
强化概率公示贴出去以后，论坛上有人拿两千次点击的录屏做了统计，发现实际成功率和表上差了一截，随后各种投诉一起涌进来。有人身上明明挂着保护符，失败时照样掉了一级；保护符没被吃掉却也没起作用，背包里少了一张；一把武器在两个窗口连点，等级只加了一，材料却扣成两份；界面显示成功率四成，结算走的是另一份配置，公示表躺在另一个目录；已经满级的装备还能继续塞材料，扣完才提示到顶；强化成功的瞬间装备从角色绑定变成可交易，拍卖行立刻能看到；属性预览里暴击加的是旧值，穿上看面板又不一样；机房断电重启后，之前垫的连续失败次数归零，保底从头再攒；把强化等级转到另一件底子上，对方原有的等级被无声覆盖，材料也不退；分区数据要等值班同学手动推一次，外区玩家看到的是昨天晚上的等级；保底进度按账号记而不是按部位，换一把武器也继承同一份计数；失败降级规则只写在帮助页，实际扣的是耐久。这些都落在 gear_forge.py 的 GearForge 里，preview、forge、transfer、protect、snapshot 各改过一版以后互相打架。我期望扣材料和改等级在同一个事务里，同一条强化链上的请求按版本号排队，概率只有一份来源，满级直接挡回去，绑定状态在操作前后保持连续，保底跟着装备走并在重启后能读回来，转移前先看目标状态，两区数据比对时带上版本，失败到底掉不掉级给出确定结论。随包附带的回归脚本我连着跑了两轮，第一轮就卡在第三条。

## 运行方式
```bash
python -m pytest tests -q
```
