# GSB Bugfix Task
## 题面
远程证明服务上线后，有几台服务器的 PCR 值和度量日志对不上，运维怀疑是日志处理的问题。日志里条目的顺序和 PCR 扩展顺序不一致，重放出来的值自然不对；同一个文件被度量两次，去重逻辑把第二次的条目删了；模板哈希从 sha1 换成 sha256，旧日志直接重放失败；某些条目的 PCR 索引缺失，代码默认填了 10；文件被改动后度量值没有变化，缓存没有失效；日志尾部被截断，校验却返回成功；多核并发度量时日志交错写入，条目拼到了别人后面；文件名里带换行，解析整段错位；度量策略排除了 /tmp，攻击者就把载荷放到 /tmp；校验工具不限制条目数，一份畸形日志能把内存打满。ima_measure_log.py 的 MeasurementLogReplayer 要按 IMA 日志格式解析每条记录，识别哈希算法，按 PCR 索引和顺序重放扩展值，尾部不完整直接判失败，并发写入按序号排序，文件名做转义处理，检查策略覆盖范围，条目数设上限，并输出每个 PCR 的期望值与实际值。test_ima_measure_log.py 的十五个用例目前全部失败，覆盖顺序错乱、重复条目、算法切换、索引缺失、缓存失效、尾部截断、并发交错、换行文件名、策略盲区、条目上限、空日志、非法模板、PCR 越界、重放一致性和结果隔离。

## 运行方式
```bash
python -m pytest tests -q
```
