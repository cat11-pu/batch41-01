# GSB Bugfix Task
## 题面
双机房出口网关换成 VRRP 主备后，业务在凌晨切了三次，每次都是两边同时回包。vrrp_state_guard.py 的 VrrpFsm 负责通告、选举和抢占，现在同一个 VRID 在两个广播域里同时活跃，双主都回应虚拟网关的 ARP；优先级相同时不比 IP 地址大小，两台设备都认为自己是主；preempt 明明关了还会抢占，业务每次都要抖一下；通告间隔不一致，备份侧把正常的慢包误判成主机离线；认证字段不校验，伪造一个 VRRP 包就能把主机顶掉；虚拟 MAC 没按 VRID 生成，接入交换机的 MAC 表学得乱七八糟；skew time 没有参与计算，故障恢复后两边同时抢主；TTL 不是 255 的报文也接受，跨网段注入的包能直接改状态；校验和错误的包仍被处理，坏包也能触发切换；上行链路 tracking 脚本失败却不降优先级，故障机继续当主；脑裂后两边都发免费 ARP，网关 MAC 在交换机上反复变；设备重启后直接进 Master，没有等待 skew time。值班同学现在只敢把备机断电，怕它一上线又抢。机房之间只有一条带外链路，真双主的时候连远程登录都进不去，业务方已经要求把切换窗口改到周末，现在谁也不敢签字。要求选举、抢占和 tracking 三部分各自有明确状态，任何异常报文都不能改变主备关系。仓库自带的那十五个用例，眼下全部失败，没有一条能立住。

## 运行方式

```bash
python -m pytest tests -q
```
