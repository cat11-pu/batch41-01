# GSB Bugfix Task
## 题面
密钥服务做了三区域副本，主区域轮换密钥后，跨区读取开始间歇性失败。主区域已经切到新版本，副本延迟八分钟才同步，这期间跨区解密全部报版本不存在；副本上的版本号偶尔回退，旧密文被拿新版本去解；主区域把密钥标记为禁用，副本的同步队列把这条事件排在旧版本写入之后，副本仍然可以解密；删除事件的墓碑被副本的压缩任务提前清理，副本把密钥又复活了；两个区域同时发起轮换，产生两个分叉版本，谁也合不回去；版本号按字符串比较，v10 被排在 v9 前面；副本只同步当前版本，历史版本被清掉，旧数据再也解不开；跨区请求重试打到不同副本，同一份密文时而成功时而失败；审计只记主区域的操作，副本侧完全空白；副本导入密钥材料时没有校验完整性，坏材料也能上线。kms_replica_version_sync.py 的 KmsReplicaVersionSync 要用版本向量记录各区域进度，版本号按数值单调比较，禁用和删除事件按序传播且墓碑不可压缩，分叉时按确定的冲突规则收敛，保留历史版本用于解密，读请求按版本路由到可用副本，重试保持同一副本或同一版本，所有区域写审计，材料导入前校验完整性。test_kms_replica_version_sync.py 的十五个用例现在全部报错，压的是同步延迟、版本回退、事件乱序、墓碑清理、双写分叉、字符串比较、历史丢失、重试漂移、审计缺失、材料损坏、空版本、重复同步、版本冲突、跨区读一致和状态隔离。

## 运行方式
```bash
python -m pytest tests -q
```
