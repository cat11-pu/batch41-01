# GSB Bugfix Task
## 题面
数据中心互联换了新的 BFD 实现，割接当晚两条专线在几分钟里反复 Down，业务跟着抖。bfd_session_fsm.py 的 SessionFsm 负责状态迁移和计时器，现在检测倍数配成 1 也接受，链路轻微抖动就把邻居抖断；收包间隔小于协商值不拒绝，高频包把 CPU 打满；Echo 模式的回环包从错误接口发出，会话永远建不起来；认证密钥轮换时新旧密钥没有重叠窗口，切换瞬间全部 Down；Poll 位置位后没在 Final 里回应，远端一直等；管理 Down 和物理 Down 没区分，恢复后没有重新协商；多跳会话没设 TTL，跨三层收不到还显示 Up；AdminDown 状态收到 Down 包直接跳 Init，出现非法迁移；抖动抑制只按次数不按时间，频繁闪断被完全掩盖；两套实例共用同一个 discriminator，回包串到别的会话；会话表只存内存，主备切换后所有邻居重建；几千个会话共用一个计时器线程，检测延迟到秒级。传输侧说割接前用旧实现跑了半年没出过这种事，新实现上线后故障面反而扩大了，值班同学怀疑计时器和认证轮换没有配合好，他们要求先保证状态迁移合法，再谈性能调优，现在只能先回滚旧版本顶着，压力很大。要求状态机、认证和计时器在重启与主备切换后仍然一致，不能因为抖动把业务打断。仓库里的十五个用例，眼下没有一条能过。

```bash
python -m pytest tests -q
```
