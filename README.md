# GSB Bugfix Task
## 题面
运营给全服补发一批道具，批次跑完后玩家说没收到，也有人说收到了两份。同一批次重跑，已经领过的玩家又收到一份；批次清单写的是八千份，实际只落了七千多，少了哪些人查不出来；邮箱满的玩家被静默跳过，运营那边显示全部送达；附件绑定状态在批量发放时丢了，补发的绑定装备变成可交易；补发邮件的过期时间按批次创建时间算，发出去就只剩两天；玩家删掉邮件后重跑批次，又收到一封；跨服玩家按源服角色编号发放，目标服根本收不到；批次执行到一半进程崩了，没有断点，重跑只能全量再来；背包满的玩家只发了金币，邮件却标成全部领取；运营撤回批次，已领取的没扣回，未领取的也没删；发放记录只写了一份日志，客服没法按玩家查。parcel_batch_delivery.py 的 ParcelBatchDelivery 负责 plan、dispatch、retry、revoke 和 audit，批次清单和玩家收件箱没有对账。希望批次、角色和附件三者做幂等，发放前校验邮箱容量并留回执，绑定属性随附件走，过期时间从实际发放时刻算，删除用软删除并留标记，跨服按全局角色编号，执行过程记录批次内偏移可续跑，部分领取事务化，撤回按已领和未领分别补偿，发放台账可按玩家回查。test_parcel_batch_delivery.py 的十五个用例现在没有一条通过，压批次重跑、清单对账、邮箱满、绑定丢失、过期起点、删除重发、跨服、断点续跑、部分领取、撤回、台账、幂等和回执。

## 运行方式
```bash
python -m pytest tests -q
```
