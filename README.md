# GSB Bugfix Task
## 题面
远程办公网关换成 WireGuard 以后，出差的同事经常连不上，日志里握手一直重试。握手初始化报文的时间戳不校验，旧包重放也能建立会话；cookie 回复不验证，源地址被伪造时 CPU 直接打满；同一个索引的握手响应被重复处理，生成了好几套密钥；预共享密钥没有混进派生流程，配了等于没配；允许地址列表的最长前缀匹配写反，流量走到了不对的节点；换过密钥以后旧值立刻删除，在途的包全被丢掉；保活报文没有速率限制，空闲连接互相打心跳；传输包的接收索引不校验，包被投到别的会话；抗重放窗口在重启后清零，旧包可以重放；IPv6 与 IPv4 的允许地址混在同一棵树里，地址族匹配串了；握手报文长度不对也不拒绝，解析时越界读；多个工作进程各自维护会话表，回包落到没有密钥的进程。运维眼下只能把出问题的节点摘掉重启，用户已经抱怨一周。这套网关同时承载办公和运维两条通道，断一次影响所有远程值班，客户端版本从旧到新都有，行为还不完全一致，希望能先灰度一个节点，现在只能整体回退。要求握手、密钥和会话索引能互相对得上，重启和轮换都不能打断在途流量。自带的十五个用例，通过数一直是零。

## 运行方式
```bash
python -m pytest tests -q
```
