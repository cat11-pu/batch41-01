# GSB Bugfix Task
## 题面
边缘负载均衡启用 PROXY protocol 之后，审计日志里的源地址开始出现内网地址，风控说有些请求根本追不到人。proxy_header_trust.py 的 ProxyHeaderTrust 负责解析和信任边界，现在来自非可信源的 PROXY 头也被采信，客户端自己写一个就能伪造源地址；v1 和 v2 混用时按字符串切分，二进制头被解析成乱码；LOCAL 命令和 PROXY 命令不区分，健康检查被当成真实用户连接；地址族是 UNSPEC 还去读地址字段，直接越界；长度字段大于实际缓冲区不拒绝，继续读到下一个请求；TLV 的类型和长度不校验，SSL 信息解析越界；v2 的 CRC32C 不校验，坏头照样进入转发；多个 PROXY 头只取第一个，链路上后加的完全覆盖不了；源端口为 0 也接受，会话表键直接冲突；代理头和 TLS ClientHello 在同一个包里时偏移算错；连接复用后第二个请求沿用第一个的源地址，审计串号；解析失败时静默回退到 socket 地址，绕过整个信任链。安全队的意思很明确，先把伪造入口堵住，再谈日志补全。这套负载均衡前面还有一层 CDN，真实源地址本来就要靠代理头传递，风控的溯源报告已经交到管理层，现在只能先收紧信任范围。要求信任边界、版本解析和失败处理三段分开，非可信来源的头一律不能采信。十五条用例跑完一轮，没有一条给出通过。

```bash
python -m pytest tests -q
```
