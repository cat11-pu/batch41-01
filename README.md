# GSB Bugfix Task
## 题面
公司把内网访问切到零信任网关，连接器按区域部署，最近分支机构的同事经常连不上，安全那边还发现策略没生效。健康检查已经失败的连接器还留在候选池里，请求被送过去直接超时；策略版本落后的节点继续按旧规则放行，新加的拒绝规则形同虚设；会话在两个连接器之间来回漂移，源地址一变就触发重新认证，死循环；选路按最近上线时间而不是延迟，跨洲用户被送到最远的节点；连接器下线时会话不迁移，用户正在传的文件直接断；同一用户的请求被分散到两个区域，跨区会话状态不同步；策略下发到一半连接器重启，只加载了前半段规则；证书过期的连接器仍然参与选路；会话表没有上限，扫描器打了几万条把内存吃满；审计只记连接器编号，不记当时生效的策略版本。ztna_connector_route.py 的 ZtnaConnectorRouter 要做健康探测、策略版本单调下发、应用到连接器按显式映射、按延迟和区域打分、会话粘性与下线迁移、连接器证书有效期检查、会话表上限，审计同时记录连接器和策略版本。test_ztna_connector_route.py 的十五个用例目前全部失败，压的是健康假阳性、版本落后、会话漂移、选路偏差、下线断流、会话分片、半段规则、证书过期、会话上限、审计缺版本、空候选、策略冲突、迁移失败、重复会话和状态隔离。

## 运行方式
```bash
python -m pytest tests -q
```
