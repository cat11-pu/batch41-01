# GSB Bugfix Task
## 题面
公司推零信任接入，终端健康度由客户端上报、服务端算分，最近安全审计发现好几台明显不合规的机器一直能进核心系统。补丁级别过期三天的设备仍被判为合规，原因是评估结果缓存没有跟着补丁时间失效；用户在评估过程中从公司网切到咖啡店 Wi-Fi，旧网络位置的结论覆盖了新结果；同一设备并发触发两次评估，后到的旧快照把新快照盖掉；磁盘加密明明关着，总分还有八十分，权重表里根本没有这一项；设备离线超过宽限期也不降权；策略版本升级后，已经签发的会话不会重新评估；风险分从二十跳到九十，手里的令牌照样能用；评估服务超时被当成合规放行；一个用户多台设备时取平均分，而不是按最差设备算；评估记录里没有设备标识，事后追不到是哪台机器。posture_eval_loop.py 的 PostureLoop 要为每次评估生成单调递增的快照版本，按 TTL 和事件双重失效，超时和缺项一律失败关闭，多设备按最差结果聚合，策略版本变化触发重评，风险跃迁时联动令牌降权和撤销，所有判定带设备标识和命中的策略项。test_posture_eval_loop.py 的十五个用例现在全部失败，压的是缓存过期、网络切换、并发覆盖、权重缺失、离线宽限、策略升级、令牌未撤销、超时放行、最差设备、审计缺字段、快照回退、空上报、重复评估、撤销传播和状态隔离。

## 运行方式
```bash
python -m pytest tests -q
```
