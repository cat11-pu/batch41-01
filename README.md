# GSB Bugfix Task
## 题面
多云边界路由器这周出了两次环路，监控上看到流量在两家云之间打转。bgp_path_arbiter.py 的 BestPathArbiter 负责入站更新和选路，现在 AS_PATH 里出现自身 AS 也不检测，环路路由照样装进 FIB；AS_SET 和 confederation 段的长度算法不一致，比较结果失真；LOCAL_PREF 只在 iBGP 生效，eBGP 学来的路由覆盖了本地策略；MED 只在同一邻居 AS 内比较，多邻居场景直接忽略；eBGP 更新没改写 NEXT_HOP，下一跳指向不可达地址；隐式 withdraw 没处理，同一前缀的旧属性残留；route-refresh 之后旧路径没撤销，FIB 里出现两份；graceful restart 的 stale 路由超过时限仍参与选路；max-prefix 超限只告警不断邻居，对方继续灌路由；同一前缀多路径的哈希不稳定，设备重启后选路结果变了；收到 AS0 的公告没有拒绝，流量被引向黑洞；并发 UPDATE 和 WITHDRAW 没按序应用，最终状态全看调度。值班同学对比了故障前后的配置，发现新加的几家云都用了私有 AS 和对等互联，路径属性比原来的单线复杂得多。更麻烦的是，两家云的对等互联配置不一样，变更窗口又撞在一起，现网已经开始丢包，环路必须先止住，边界设备已经重启过一轮，问题依旧，现场很乱，压力很大。要求把路径属性解析、选路状态和撤销顺序统一起来，任何异常公告都不能影响现网转发。仓库自带的十五个用例，眼下全部失败，没有一条能站起来。

## 运行方式
```bash
python -m pytest tests -q
```
