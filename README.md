# GSB Bugfix Task
## 题面
分支机构的 IPsec 隧道这周反复重连，监控上看到隧道刚起来又断。ikev2_sa_negotiator.py 的 SaNegotiator 负责 IKE_SA 和子 SA 协商，现在 IKE_SA_INIT 响应带 COOKIE 时发起方不回重试，入口压力一大就有一半握手失败；多个 proposal 里代码只取第一个转换，忽略了双方共同支持的 DH 组，派生出的密钥长度对不上；nonce 长度没校验，短 nonce 也进密钥派生；响应方的 SPI 和子 SA 绑定错位，两条隧道共用一套密钥；双方同时重协商时两条新 SA 互相删除，流量中断；子 SA 的流量选择器没收窄，/0 策略把无关流量也吸进隧道；删除一个子 SA 的 DELETE 负载把整个 IKE_SA 一起拆了；DPD 超时和重传计时器互相打架，探测风暴里重复建 SA；NAT 检测后端口浮动到 4500，但 NON-ESP 标记和校验和没按规范处理，对端全部丢弃；重协商后 ESP 重放窗口直接清零，旧包要么被重放要么被误丢；IKE 消息分片没重组，带长证书的认证总是失败；设备重启后 SA 不落盘，所有分支一起掉线。分支侧的路由器型号很杂，有的对 NAT-T 和分片支持不一样，总部要求先保证重协商不中断业务，再谈分支扩容，现在分支每天都在报障，上面要求本周内解决，总部压力很大。要求把协商状态、重协商冲突和 SA 生命周期做扎实，NAT 环境和设备重启都要能恢复。自带的十五个用例，目前一条也没通过。

