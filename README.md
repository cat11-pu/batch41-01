# GSB Bugfix Task
## 题面
网关集群做完滚动发布以后，mTLS 客户端开始随机出现握手失败，更严重的是几张已经吊销的客户端证书还能继续访问内部接口。集群里一部分节点换了新的会话票据密钥，一部分还留在旧密钥，客户端恢复会话时被随机分到不同节点；旧 epoch 的票据过了约定宽限期仍然可用；会话恢复路径为了省一次往返，直接跳过了客户端证书和吊销状态检查；0-RTT 数据在票据轮换后被原样重放；票据没有绑定客户端证书指纹，换一张证书也能恢复同一个会话；票据密钥 ID 生成有碰撞，偶尔解到错误的 key；节点重启后票据密钥只存在内存里，恢复请求整片失败；early data 没有大小上限，单个连接能把接收缓冲吃满；客户端证书换绑服务账号后，已恢复的会话仍按旧身份放行；旧 epoch 密钥一到点就被删除，宽限期内的票据直接解不开。session_ticket_epoch.py 的 TicketEpochKeeper 要把票据密钥按 epoch 版本化并落盘，恢复会话时重新校验客户端证书链和吊销状态，0-RTT 只允许安全方法并接入重放缓存，票据绑定客户端证书指纹与 ALPN，epoch 轮换保留宽限期密钥，切换原子完成，返回协商结果和拒绝原因。test_session_ticket_epoch.py 的十五个用例目前全部报错，分别盯住跨节点不一致、旧票据宽限、恢复跳过校验、0-RTT 重放、换证书复用、密钥 ID 碰撞、重启丢密钥、early data 上限、身份缓存、密钥早删、空票据、过期 epoch、ALPN 不符、持久化恢复和内部账本隔离。

## 运行方式
```bash
python -m pytest tests -q
```
