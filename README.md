# GSB Bugfix Task
## 题面
私有云 overlay 扩到三个机房后，虚机开始间歇性丢包，同一网段的两台机器 ping 时通时不通。vxlan_fdb_learner.py 的 FdbLearner 负责 MAC 学习和 VTEP 选择，现在同一 MAC 在两个 VTEP 下同时出现，FDB 反复改写，流量来回抖；MAC 迁移没有序列号比较，旧 VTEP 迟到的包把表项改回去；VNI 隔离没做，跨租户同 MAC 直接二层互通；BUM 流量按单播复制列表发，新加入的 VTEP 收不到广播；ARP 抑制表项过期后没重新学习，虚机 ARP 全部超时；外层 UDP 校验和为 0 时被当成合法，坏包进入解封装；MTU 没算 VXLAN 开销，大包全丢还不回 ICMP；环路检测只看物理口，overlay 逻辑环路无限泛洪；FDB 老化按本地时钟，跨设备不一致造成黑洞；EVPN 类型 2 路由的 MAC 长度字段异常也解析，越界读；并发学习和老化同一表项没有锁，偶发崩溃；控制器下发全量路由时覆盖本地静态表项，业务网段直接消失。运维已经把三个机房的 FDB 都导出来对比，发现配置基线本来就不一致，他们要求先把学习、老化和控制器同步理清，再排查物理链路，现在已经影响跨机房迁移，业务方已经在催，非常紧急，机房迁移窗口只剩两天，运维压力很大，必须尽快。这块要把学习、老化和控制器同步放在同一份状态里，租户隔离和环路必须守住。十五条用例跑到现在，通过数还是零。

