# GSB Bugfix Task
## 题面
视频会议自建 TURN 中继后，NAT 后面的用户能连上，但安全队说中继能被拿去访问内网。turn_allocation_guard.py 的 AllocationGuard 负责分配、权限和通道绑定，现在 Allocate 请求要 TCP 中继也照样分配 UDP；nonce 只发一次却不校验过期，重放能反复建分配；权限没绑定对端地址，任意主机都能借这条中继发数据；ChannelBind 的通道号冲突时后绑定覆盖前一个；分配 lifetime 超过上限不截断，端口被长期占着；XOR-MAPPED-ADDRESS 的地址族和长度对不上也解析；消息长度字段大于实际报文时不拒绝，越界读；FINGERPRINT 校验失败仍继续处理；同一五元组并发建分配，两个都成功，回包随机走一条；到期清理只扫一半哈希桶，端口泄漏到耗尽；ICE 角色冲突时两端都当 controlled，候选对永远连不通；中继允许访问回环和内网，TURN 成了内网穿透工具。安全队用一个简单的脚本就从中继打到了元数据地址，过程没有触发任何告警，运维担心直接关掉中继会让一部分 NAT 用户彻底连不上，现在需要先止血再补审计，同时保留正常用户的连通性，这件事已经上报，安全队还在等回复，合作方也在追问恢复时间，会议厂商也在催。需要把分配生命周期、权限和地址校验一起修，异常请求要明确拒绝。十五条用例逐条验证，全部以失败告终。

```bash
python -m pytest tests -q
```
