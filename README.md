# GSB Bugfix Task
## 题面
边缘网关刚把图片站切到 HTTP/3，首页偶发白屏，抓包看是响应头解不出来。qpack_table_sync.py 的 HeaderTableSync 管编码器和解码器的动态表同步，现在一条请求流被重置后，动态表的插入计数不回滚，后面所有相对索引整体错位；同一个头部连续插入两次也不去重，表容量几秒就满；驱逐条目时还有没完成的引用，解码出来是空值；阻塞流没有上限，一个慢客户端能把整条连接卡住；静态表和动态表的索引空间混着算，绝对索引和相对索引解析反了；Huffman 解码在长度不足时越界读，进程偶发崩溃；头部列表超过上限不返回错误，内存直接翻倍；GOAWAY 之后新流还复用旧编码器状态，前后端表对不上；网关有八个 worker，各自维护一份动态表，负载均衡一切换就解码失败；表容量更新指令没按到达顺序应用，容量减到负数也照收；并发插入和驱逐没有互斥，偶尔同一个槽位被写两次；进程重启后编码器从空表开始，客户端却还在引用旧表。值班同学怀疑和最近启用的多路复用有关，但还没定论。这块要按 HTTP/3 的流依赖和表状态做成可恢复的一致视图，慢流不能拖垮整条连接，异常输入要稳定报错而不是崩。那十五条用例现在的状态是全红，一条都没过去。

