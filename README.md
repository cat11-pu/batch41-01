# GSB Bugfix Task
## 题面
主从 DNS 昨晚切主之后，从库的区文件里还留着已经删掉的解析记录，几个内部域名指到了旧地址。axfr_journal_guard.py 的 ZoneTransferGuard 负责 AXFR、IXFR 和 journal 游标，现在 IXFR 被降级成 AXFR 时从库没清空旧记录，删除的条目全部残留；SOA 序列号按 32 位回绕比较写错，新版本被当成旧版本拒绝；多消息 AXFR 流里记录顺序错乱，从库按到达顺序直接落盘；TSIG 只校验第一条消息，后续消息没签名也接受；TSIG 时间窗按本地时区算，跨时区节点总是签名失败；传输 ACL 只匹配源地址前缀，兄弟区也能拉全量；压缩指针指向自身形成环，解析器无限循环；单次传输的记录数没有上限，一个区就能把内存吃光；从库在传输中途断线，临时文件没清理，下次启动加载半份区；两个从库同时拉，主库把同一个 journal 游标推进两次；NOTIFY 比数据先到，从库立即查询拿到旧 SOA；区数据超过 journal 保留期，IXFR 回退逻辑没有重建全量。值班同学说切主前一切正常，切完十分钟后开始出现旧记录，从库重启一次会好一阵，过几个小时又反弹，怀疑和 journal 游标以及临时文件的清理有关，目前只能靠人工重建区文件顶着。需要把传输状态、序列号比较和落盘恢复做成一个事务，断线重传不能留下半份数据。十五条用例从头跑到尾，没有一条能收尾通过。

## 运行方式
```bash
python -m pytest tests -q
```
