# GSB Bugfix Task
## 题面
匹配服务做完滚动发布后，晚高峰的排队数据丢了一大半，客服说玩家等了二十分钟又被送回队尾。进程重启后内存队列清空，等待时长全部归零；票据落了库但成局记录没落库，重启后同一批人被重新匹配一次；两个节点同时扫到同一张票，各自成局，玩家收到两份入场通知；队列快照每分钟落一次盘，宕机丢掉最后一分钟的票；恢复时把已经取消的票又塞回池子；组队票只持久化了队长，队员关系丢失，成局后找不到人；停机期间票据已经过期，恢复后仍然被拉进对局；玩家重连拿到新票，旧票还留在池里；成局后创建对局失败，票已经删了，玩家卡在确认界面；优先级字段恢复后取了默认值，高优先级玩家排到普通玩家后面；两个节点写同一张票，旧版本把新版本覆盖。match_queue_recovery.py 的 MatchQueueRecovery 负责 persist、restore、claim、match 和 compensate，持久化和内存状态没有统一版本。希望票据状态全部落库，取消留墓碑，成局用幂等键，节点通过租约抢占票据，恢复时快照加日志回放，组队票整体持久化，过期在恢复时重新判定，重连复用原票，成局创建失败走补偿，优先级原样恢复，写入带版本比较。test_match_queue_recovery.py 的十五条检查现在一条都过不了，压重启丢票、重复成局、双节点抢占、快照缺口、取消复活、组队残缺、停机过期、重连双票、创建失败、优先级丢失、版本覆盖、租约、墓碑、日志回放和补偿。

## 运行方式
```bash
python -m pytest tests -q
```
