# GSB Bugfix Task
## 题面
计费网关接上 Diameter 信用控制后，月末对账多出一批重复扣费，还有用户欠费仍能上网。diameter_credit_guard.py 的 CreditGuard 负责 CCR/CCA 和配额，现在同一个 Session-Id 重复请求不检测，一次上网扣了两次费；Hop-by-Hop 和 End-to-End 标识混用，响应匹配到别的会话；Result-Code 是暂不可用却按成功处理，业务继续放行；Granted-Service-Unit 的额度累加没去重，用户余额被扣成负数；重传的 CCR-U 带着旧配额，服务器又授予一遍；多个服务节点共用一个会话，额度互相覆盖；Final-Unit-Indication 的重定向不执行，欠费用户还能继续上网；AVP 的 vendor 位和长度不校验，私有属性解析越界；信用控制会话超时后不释放，配额一直挂着；主备 PCRF 切换时会话没同步，同一用户被重复授权；并发 CCR-I 同一用户，两边都建了会话；计费日志只记请求不记授予，对账根本对不上。财务已经把这批差异单独挂账，催得很紧。这套计费链路还连着在线计费和离线话单，任何重复授予都会进账单，财务要求在下个出账周期前把差异解释清楚，厂商的补丁要下个月才能给，现在只能先关掉自动重试，运营压力很大，每天都有新投诉，财务每天都在催，大家都在等结果，都很着急。要求会话、额度和结果码三条线统一，重复请求只能幂等处理。自带的那十五个用例，目前全部停在失败。

