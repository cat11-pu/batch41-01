# GSB Bugfix Task
## 题面
服务器双上行做 LACP 聚合后，虚拟化平台经常报警，说同一台宿主机一会儿通一会儿不通。lacp_bundle_guard.py 的 BundleGuard 负责 LACPDU 和成员口状态，现在 actor 和 partner 的系统优先级不比较，两端都认为对方的信息过期；端口还在 defaulted 状态就被拉进聚合，成员口反复 up/down；collecting 和 distributing 没有同时置位就开始转发，丢包丢得毫无规律；短超时和长超时混用，一端三秒一端九十秒，成员被误踢；LACPDU 的 TLV 长度不校验，畸形包解析越界；同一聚合组里成员口速率不一致也被选中，哈希严重倾斜；最小链路数没配置，成员全 down 聚合口还显示 up；静态聚合和动态 LACP 混配，两端模式根本对不上；成员口 flap 后没有冷却，反复震荡把交换机 CPU 拉高；LACPDU 源 MAC 不校验，伪造包能把恶意成员拉进来；聚合口 MAC 学习表没同步到成员口，回包走错链路；设备重启后聚合组 ID 重新分配，配置和实际对不上。运维已经换成单链路顶着，带宽掉了一半。宿主机上跑的是核心数据库和消息队列，链路一抖就触发主备切换，交换机厂商和服务器厂商互相说是对方的问题，运维夹在中间很难受，前后开了三次会，已经拖不起。要求成员状态、超时和聚合逻辑按标准走，任何成员异常都不能影响整组转发。十五条用例逐条执行，全部失败。

