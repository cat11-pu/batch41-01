# GSB Bugfix Task
## 题面
设备团队给摄像头做 OTA 升级，安全评审用一份旧固件就刷回了有漏洞的版本。旧版本的签名本身有效，设备不检查版本高低，降级请求照样通过；防回滚计数器存在普通分区里，刷机工具一条命令就能清零；固件包里的型号和硬件版本字段没有校验，另一款设备的包也能刷进来；增量包只校验最终哈希，基线是哪个版本完全不管；签名链只验了叶子证书，中间证书可以换成攻击者自签的；A/B 分区切换后回滚计数没有同步，切到 B 分区又回到旧计数；签名证书过期时设备时钟还没同步，校验直接跳过；密钥吊销列表没有随包下发，泄露的签名密钥继续可用；恢复模式刷机完全绕过签名校验；双签策略要求厂商和客户各签一个，实际任意一个签名就放行。firmware_rollback_gate.py 的 FirmwareRollbackGate 要校验完整签名链和设备型号、维护单调防回滚计数器并跨分区同步、校验增量包基线、执行双签阈值、检查密钥吊销、恢复模式同样验签、设备时钟不可信时失败关闭、审计记录版本和签名者。test_firmware_rollback_gate.py 的十五个用例现在全部失败，覆盖旧版降级、计数器清零、型号错配、基线缺失、中间证书、分区不同步、时钟跳过、吊销缺失、恢复模式、双签降级、空包、重复版本、签名链断、硬件版本和状态隔离。

## 运行方式
```bash
python -m pytest tests -q
```
