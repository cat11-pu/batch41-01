# GSB Bugfix Task
## 题面
内部服务网格从 Kerberos 迁到约束委派之后，渗透测试拿一张普通用户的凭据就打进了财务系统。没有可转发标记的凭据仍然被拿去做代理；自服务换出来的身份凭据被直接当成本人，绕过了能否转发的判断；允许委派的服务列表按前缀匹配，evil-svc 也能命中 svc；PAC 里的组被裁掉以后签名没有复核，后端照样按高权限放行；跨域信任时把引用凭据当成域内凭据使用；凭据缓存并发读写，偶尔取到别人的身份；代理凭据没有记录发起服务，审计里看不出是谁代谁；服务账号在目录里标了不可委派，请求还是成功；委派链走到第二跳没有深度限制；凭据里的中转路径完全没检查；服务名前后带空格也被当成同一个服务。constrained_delegation_ticket.py 的 DelegationTicketArbiter 要解析标志位、复核 PAC 签名、服务名逐字命中白名单、按白名单和深度放行，检查中转路径，拒绝不可委派账号，缓存按用户和服务名隔离并带版本，记录来源服务链，返回允许或拒绝的具体理由。测试目录里那十五项，现在每条都抛异常。

## 运行方式
```bash
python -m pytest tests -q
```
