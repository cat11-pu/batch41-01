# GSB Bugfix Task
## 题面
值班手机半夜响了，视频会议服务端换成 QUIC 之后，地铁里切 Wi-Fi 的用户一大片断流。quic_path_migrator.py 里的 PathMigrator 负责收包、路径验证和提交迁移，现在新四元组的第一个包不做路径验证就直接切过去；NAT 重绑定和真正换网走同一个分支，端口一变反而被当成攻击丢掉；迁移完成后还在用旧路径的拥塞窗口和 RTT，新链路带宽被低估，画面一直糊；反放大额度按旧地址统计，新地址短时间内能收到超过三倍的数据；两个候选路径并发验证时，后完成的把先完成的覆盖，连接在两路之间来回抖；验证超时没有回退，会话永久停在验证中；连接 ID 路由表没跟着更新，后续包被投到旧 worker；包号空间没有按新路径重置，重组窗口错位，丢包率飙到两成；服务端下发的 preferred address 客户端不认，重连风暴把入口打满；迁移窗口里的 0-RTT 数据被重放，业务收到重复的举手和聊天消息；开关里明明关了迁移，新路径还是被接受；进程滚动重启后迁移状态全丢，所有移动端一起断。客户端版本回滚后现象没有变化，说明问题在服务端。要求把路径验证、迁移状态和路由更新收成一致的状态机，弱网切换不能中断会议，也不能让旧路径的额度泄漏到新路径。仓库自带的十五个用例，眼下没有一条能跑通。

```bash
python -m pytest tests -q
```
