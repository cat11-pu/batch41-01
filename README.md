# GSB Bugfix Task
## 题面
多租户集群上线 NetworkPolicy 之后，安全演练发现默认拒绝根本没生效，几个测试 Pod 还能互相访问。netpol_selector_eval.py 的 PolicyEvaluator 负责选择器和端口匹配，现在空的 podSelector 被当成不匹配，默认拒绝策略实际是空转；namespaceSelector 和 podSelector 写在同一个 peer 里被当成或关系，跨命名空间全放行；ipBlock 的 except 没做减法，本该排除的网段仍能访问；命名端口没解析成实际端口，策略匹配到 0；ingress 和 egress 同时命中时只应用其中一条，另一个方向裸奔；同一个 Pod 被多条策略选中，代码后写覆盖而不是取并集；endPort 字段被忽略，端口范围只匹配起点；策略更新时旧规则没撤销，命名空间删了规则还留着；DNS 出站没放行，所有服务解析超时但策略显示允许；hostNetwork 的 Pod 绕过策略直接连通节点；并发更新和查询没有版本号，读到半更新状态；策略数量上千后线性扫描，单次判定要几十毫秒。安全演练用的几个测试命名空间本来应该完全隔离，运维怀疑是策略合并时把不同命名空间的选择器当成了同一组，他们要求先把默认拒绝和端口范围做对，再补审计，现在联调计划全被打乱，很影响进度。这块要把选择器语义、策略合并和增量更新做对，默认拒绝必须是真的拒绝。自带的十五个用例，眼下全部停在失败状态。

## 运行方式
```bash
python -m pytest tests -q
```
