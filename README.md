# GSB Bugfix Task
## 题面
安全团队给服务单元加 systemd 加固指令，灰度时两个服务起不来，另一个加固完全没生效。只读保护与可写路径冲突时，后写的覆盖前面的，服务启动直接报只读；禁止提权配上 setuid 程序，实测仍然能拿到 root；私有临时目录让两个服务共享了同一处，查下来是拼错了实例名；地址族限制写成空值，被当成允许全部协议；能力边界用加号追加，没有先重置，越加越多；家目录只读和绑定路径顺序不同，挂载结果完全两样；系统调用过滤用了内核不支持的组名，启动失败却没有提示；指令名大小写写错被静默忽略；三个 drop-in 合并顺序不确定，每次发布结果都可能不同；未知指令只打一条警告，生产上一直以为已经生效。unit_hardening_parse.py 的 UnitHardeningResolver 要解析主单元与 drop-in 的优先级，逐条合并布尔、列表和空值语义，能力集合先重置再增删，检测路径与只读规则的冲突，未知指令和拼写错误按策略拒绝或显式标记，合并结果要给出最终生效值及来源文件。十五项检查从第一条起就没过，后面更不用看。

## 运行方式
```bash
python -m pytest tests -q
```
