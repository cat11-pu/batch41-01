# GSB Bugfix Task
## 题面
出海业务走三级正向代理，这周源站日志里出现了代理的账号密码，安全队直接拉了事故群。proxy_chain_hopstate.py 的 HopState 负责逐跳改包和隧道状态，现在 Proxy-Authorization 被一跳跳转发到源站，凭据完整落进业务日志；Connection、Keep-Alive、TE 这些逐跳头没在每一跳剥离，后端复用了带脏头的连接；Via 头只追加不检查，链路成环后请求无限转圈；407 挑战缓存按目标站点而不是按代理存，换出口后还带着旧凭据；CONNECT 隧道的半关闭处理错，上传到一半就断；链中某跳返回 chunked，下一跳又包一层，响应体被重复解码；绝对形式 URI 重写时保留了原 Host，第二跳按错误站点路由；链路故障切换后连接池没按出口隔离，请求从错误地区发出；代理认证失败重试没有次数上限，形成 407 风暴；traceparent 这类透传头被客户端伪造，链路追踪指向假节点；隧道空闲超时按单跳配置，链上最短的那个先把长连接掐断；并发请求共用一条上游连接，响应按完成顺序错配给调用方。安全队要求先把凭据泄漏的路径堵住，再谈链路优化，这条链路平时承载的都是合作方的对账流量，停一个小时业务就受不了。需要把逐跳头、认证状态和连接归属分开管理，链路切换不能串用户也不能泄漏凭据。十五条用例逐条跑过，通过的是零条。
