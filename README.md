# GSB Bugfix Task
## 题面
网络设备监控切到 SNMPv3 后，采集器一会儿能读一会儿报授权失败，还有几台设备的配置被改过。snmpv3_engine_guard.py 的 UsmGuard 负责引擎发现和用户认证，现在 engineID 发现响应不校验，任意引擎都能被当成权威引擎；boot counter 和时间窗不比较，旧请求可以重放改配置；authNoPriv 请求被当成无认证处理，HMAC 这一步直接跳过；认证码截断长度不校验，很短的摘要也能通过；隐私参数为空仍按加密报文解析，密文被当明文读；用户不存在时返回的错误和密码错误不一样，能枚举账号；视图控制只比 OID 前缀，只读用户能读到写视图；GetBulk 的最大重复次数没有上限，一个请求就能打满 CPU；同一个消息号并发请求响应错配，采集器拿到别的设备数据；Report PDU 的 OID 不校验，未知引擎错误被当成正常响应；trap 和 inform 的 engineID 混用，告警一直发不出去；设备重启后 engineBoots 没持久化，重放窗口直接失效。安全队是从配置变更告警里发现这事的，写权限已经停了。设备分布在全国十几个机房，采集器版本也不统一，总部安全基线要求 SNMPv3 必须开认证和加密，目前只能先回退到只读账号，值班压力很大，已经拖不起。要求引擎、用户和视图三层各自校验，异常报文只能丢弃并留痕。仓库里的十五个用例，眼下全部报失败。

## 运行方式

```bash
python -m pytest tests -q
```
